# ADR 0004. Внешний вход: WAF, LoadBalancer и ограничение источника

| | |
| --- | --- |
| Статус | Предложено, на стенде НЕ проверялось |
| Дата | 2026-08-20 |
| Затрагивает | ADR 0001 (Gateway API), ADR 0003 (PKI), раздел 21.1 пункт 8 |

---

## 1. Задача

Впустить трафик снаружи через WAF так, чтобы **обойти WAF было нельзя**.
Вход в кластер уже есть и проверен — Gateway API от Cilium (ADR 0001).
Здесь решается, как до него добирается WAF и чем закрыт обход.

Путь: клиент → WAF (терминирует внешний TLS) → **HTTPS** → адрес
LoadBalancer → Gateway → сервис. Перешифрование выбрано намеренно:
внутри контура открытого трафика не остаётся.

---

## 2. Решение

**Адреса выдаёт и анонсирует Cilium**, MetalLB не вводится. Cilium уже
датаплейн кластера; второй компонент делал бы ту же работу, и появилось бы
два места, где решается «чей это адрес».

Плата за это решение названа честно: **L2-анонсы Cilium — beta**,
отработка отказа 10–20 секунд, на ARP отвечает один узел.

**Если сеть допускает пиринг — берите BGP вместо L2.** Он снимает и
единственного лидера, и десятисекундную отработку отказа, и конфликт с
`externalTrafficPolicy: Local`, описанный ниже. L2 — вариант для сети, где
BGP недоступен.

---

## 3. Конфликт, который определяет остальное

Документация Cilium прямо говорит: L2-анонсы **несовместимы с
`externalTrafficPolicy: Local`** — сервис может анонсироваться с узла, где
нет подов сервиса, и трафик теряется.

А `Local` нужен: при `Cluster` трафик проходит SNAT, исходный адрес
подменяется адресом узла, и ограничение доступа по адресу WAF **молча
перестаёт работать** — правило будет видеть узел, а не WAF.

**Почему в нашем случае конфликта нет.** Эндпоинты сервиса Gateway — поды
`cilium-envoy`, а они DaemonSet и есть на каждом узле. Узла без подов не
бывает, и описанный отказ не наступает.

**Это рассуждение, а не проверка.** Оно опирается на то, что Envoy
развёрнут DaemonSet'ом (`external-envoy-proxy: true`). Если конфигурация
изменится — Envoy станет Deployment'ом, появится селектор узлов, — вывод
перестанет быть верным, а отказ будет выглядеть как случайная потеря
части запросов. Поэтому проверка «вход работает при выводе узла» в
разделе 6 обязательна, а не желательна.

---

## 4. Ограничение источника: два рубежа

**Первый — клиентский сертификат WAF.** Gateway требует от WAF сертификат
из `pki_infra` (ADR 0003). Не зависит ни от режима `externalTrafficPolicy`,
ни от того, кто анонсирует адрес, ни от подмены адреса при SNAT. Обход
невозможен даже изнутри сети.

**Второй — `fromCIDR` с адресами WAF.** Дешёвый и наглядный, но зависит от
сохранения исходного адреса. Оставляется как второй рубеж, а не как
единственный.

Порядок именно такой. Схема, где ограничение держится только на адресе
источника, ломается тихо: достаточно кому-то поменять
`externalTrafficPolicy` на `Cluster` — и вход открыт всем, при этом ничего
не падает и в логах ничего не меняется.

## 5. Конфигурация

### 5.1. Values Cilium

```yaml
l2announcements:
  enabled: true

# Интерфейсы, на которых отвечать на ARP. Без явного списка анонсы не
# работают, а сообщение об этом не говорит.
devices: [eth0]

k8sClientRateLimit:
  # ОБЯЗАТЕЛЬНО поднять. Умолчание — 5 запросов в секунду на весь агент, а
  # только на продление lease уходит  (число LB-сервисов) / leaseRenewDeadline.
  # При десяти сервисах это уже больше умолчания, и анонсы начинают
  # моргать под видом сетевых проблем.
  qps: 50
  burst: 100

gatewayAPI:
  enabled: true
  gatewayClass:
    create: "true"
```

И ключ, задаваемый через ConfigMap Cilium:

```
gateway-api-service-externaltrafficpolicy: Local
gateway-api-xff-num-trusted-hops: "1"
```

`xff-num-trusted-hops` равен числу прокси перед Gateway: один WAF —
единица; WAF плюс HAProxy — двойка. Слишком большое значение опаснее
слишком малого: оно позволяет клиенту подделать свой адрес заголовком.

### 5.2. Пул адресов и анонс

```yaml
apiVersion: cilium.io/v2
kind: CiliumLoadBalancerIPPool
metadata:
  name: external-ingress
spec:
  blocks:
    - cidr: 10.10.20.0/29   # адреса из сети, где стоит WAF
  serviceSelector:
    matchLabels:
      io.cilium/lb-ipam-pool: external-ingress
---
apiVersion: cilium.io/v2alpha1
kind: CiliumL2AnnouncementPolicy
metadata:
  name: external-ingress
spec:
  # Анонсировать только с worker-узлов: control-plane не должен принимать
  # внешний трафик.
  nodeSelector:
    matchExpressions:
      - key: node-role.kubernetes.io/control-plane
        operator: DoesNotExist
  interfaces: [eth0]
  externalIPs: false
  loadBalancerIPs: true
```

### 5.3. Ограничение источника

```yaml
apiVersion: cilium.io/v2
kind: CiliumNetworkPolicy
metadata:
  name: allow-waf-only
  namespace: <namespace Gateway>
spec:
  endpointSelector:
    matchLabels:
      k8s-app: cilium-envoy
  ingress:
    - fromCIDR:
        - 10.10.10.5/32      # адреса WAF
```

Клиентский сертификат задаётся на listener Gateway через
`tls.options` реализации — конкретный ключ зависит от версии Cilium и
должен быть проверен на стенде, а не переписан отсюда.

---

## 6. Что проверять

Первые три пункта — обязательные; без них проверено, что вход работает,
но не проверено, что его нельзя обойти.

| Что | Как | Ожидание |
| --- | --- | --- |
| **обход WAF** | запрос напрямую на адрес LB с постороннего адреса | отвергнут |
| **обход при `Cluster`** | временно сменить `externalTrafficPolicy`, повторить обход | должен быть отвергнут клиентским сертификатом — если прошёл, второй рубеж не работает |
| **реальный адрес клиента** | в логах приложения | адрес клиента, а не WAF |
| путь через WAF | обычный запрос | 200 |
| вывод узла | `drain` узла-лидера анонса | вход продолжает работать; измерить, сколько длится перерыв |
| ввод узла | `add-node` | новый узел участвует в анонсе |
| отработка отказа | погасить узел-лидера | измерить фактическое время, а не поверить в 10–20 с |

Строка про `Cluster` важнее, чем кажется: она проверяет не текущую
настройку, а то, что схема не разваливается от одного неверного значения.
